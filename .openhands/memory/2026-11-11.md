## Instagram — a sessão é RECUSADA (diagnóstico definitivo)

O `!keyig testar` mostrou (com os headers completos já aplicados):
```
current_user (app): HTTP 200 ❌ SESSÃO INVÁLIDA
usernameinfo (app): HTTP 200 ⚠️ status:fail
web_profile_info (web): HTTP 429
info (app): HTTP 400 ⚠️ status:fail
```

**Leitura**: os headers NÃO eram a causa (o 200+fail persistiu com os ~31
headers). O `current_user` — que devolve a conta logada quando o sessionid
presta — diz **recusada**. Ou seja: **o Instagram não aceita a sessão**, e o
`429` (rate limit) na rota web aponta **IP flag**.

Duas causas possíveis, correções opostas:
1. **cookie inválido/expirado** → renovar o cookie;
2. **IP do servidor bloqueado** (datacenter/VPS) → nenhum cookie resolve.

O diagnóstico agora mostra **o IP do servidor** e testa o `current_user` nas
**duas casas** (app e web) — para separar as duas.

### O que NÃO fazer (decisão registrada)
Não vale "engenharia reversa do Instagram": o protocolo privado já está
documentado em implementações mantidas (instagrapi, aichemy). O que resta **não
é protocolo** — é a decisão do servidor (IP/sessão). RE não muda isso.
